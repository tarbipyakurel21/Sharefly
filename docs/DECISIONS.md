# Decisions

- 2026-11-14: Repo contained PatternWitness, not ShareFly. Owner chose to replace it; old code is in `legacy/`.
- SQLite via `better-sqlite3@11` instead of Prisma: no codegen/engine download, schema stays portable. v13 segfaulted on Node 22.12.
- Raw SQL in `lib/db` rather than an ORM; JSON lists stored as TEXT.
- AI providers implemented: `anthropic` (fetch, no SDK), `mock`, `none`. OpenAI/Google intentionally not implemented (no demo value).
- AI model default `claude-sonnet-5-5`; configurable via `ANTHROPIC_MODEL`. Not verified against a live key in this environment.
- Uploads: local disk (`data/uploads`) served by a route handler.
- CoStar / Matterport: no documentation or credentials were found in the repository, so no endpoint is called. The null provider stays active and no related UI renders.
- Distance: haversine between neighborhood centres from a static table; unknown neighborhoods have null coordinates.
- 2026-11-14: "View in your room" (AR) uses Google `<model-viewer>`: WebXR on Android Chrome, AR Quick Look on iOS (USDZ converted on device). Loaded as the prebuilt CDN bundle because the npm package's three peer range (^0.183) conflicts with ours (0.187); the bundle carries its own three, so the console shows a harmless "multiple instances of three.js" warning.
- The AR model is the same procedural shape the planner draws (`lib/room/model.ts`), exported to GLB in the browser. It is a to-scale stand-in, not a scan, and the UI says so. AR scale is locked (`ar-scale="fixed"`) and the button only appears when the giver has entered measurements; otherwise it explains why it is unavailable.
- Scene Viewer (Android's non-WebXR fallback) is not enabled: it needs a public URL to the model and our model is a client-side blob.
- 2026-11-14: Laptop alternative to AR: "In a photo of my room". The person marks a line of known length (e.g. a door) to set pixels-per-meter, then the same procedural model is drawn over the photo with an orthographic camera, plus turn and camera-angle sliders. It is labeled approximate (a flat photo has no depth; accurate near the measured line). The photo is never uploaded; it stays as a local object URL. "Door height (often 6'8\")" is only a fill-in suggestion the person confirms.
- 2026-11-14: HEIC support via `heic-to` (LGPL-3.0, maintained, current libheif) rather than `heic2any` (MIT wrapper, but unmaintained and ships a 2020 libheif that fails on newer iPhone photos; libheif is LGPL either way). Format is detected by magic bytes (`lib/image-decode.ts`) because browsers often report HEIC with an empty MIME type. Native decode is tried first (Safari), the converter is lazy-loaded otherwise. The server still only accepts JPEG/PNG/WebP; listing photos are re-encoded to JPEG on the device before upload.
- 2026-11-14: Room photo now places the item automatically instead of asking for a measurement first. A single photo has no depth, so we estimate the camera (about 1.4 m high, tilted 8 degrees down, lens from EXIF FocalLengthIn35mmFilm when present, else 26 mm) and render with a matching perspective camera; taps map to floor positions. Labeled as an estimate. Marking a door (floor to top) is optional and solves the camera height exactly (`cameraHeightFromVertical`). Considered but not done: AI vision or monocular depth models (large downloads, still approximate, and the AI provider is off by default). Calibration supersedes the orthographic pixels-per-meter approach recorded above.
