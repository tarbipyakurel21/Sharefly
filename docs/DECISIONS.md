# Decisions

- 2026-11-15: Replaced the optional listing video with an optional 3D model added while creating the listing (`POST /api/uploads/model`, `.usdz`/`.glb`, magic bytes, 30 MB, sign-in and rate limit). The listing stores `model`; the browser reads the model's bounding box and sends width/depth/height (only when 2 cm to 10 m) so the size is filled in, and the owner can change it afterwards. The video upload route, `videoUrl` field and player are removed; byte-range support for local uploads stays. Same Vercel ~4.5 MB request-body limit applies. Unit tests pass (149); not tried with a real scan.
- 2026-11-15: The Matterport apartment stage now has a request button under the tour: when a piece is selected, it is someone else's available listing with a confirmed size, and it fits the room's size (`fitStatus`), the button "It fits. Request <item>" records interest. Caveat: for apartment rooms the size can be a floor-plan estimate or a Matterport measurement the person adjusted, so "fits" is only as good as that room size. Also swapped three.js `USDZLoader` (deprecated) for `USDLoader`. Not tried in the browser.
- 2026-11-15: In the 3D room planner, selecting a piece that came from someone else's available listing and whose fit is confirmed ("fits") shows an "It fits. Request this item" button that records interest (`POST /api/listings/[id]/interest`, same as the item page). It never appears for unconfirmed or too-big pieces, your own items, or items no longer available. The Matterport apartment stage does not do fit checks, so it has no request button. Not tried in the browser.
- 2026-11-15: Everything on ShareFly is free, and the cart is removed (cart page, `/api/cart*` routes, `cart` collection index, header icon, "Add to cart" button). Price inputs are gone from listing creation, the owner panel and the wishlist form; cards and item pages show "Free"; the API ignores any price (`priceCents` is always 0). Wishlist text such as "under $30" is still parsed by `lib/matching/parse.ts` and harmless. Old `cart` rows and old non-zero prices in an existing database are not deleted/changed (a reseed resets prices).
- 2026-11-15: Listings can have one optional short video (`videoUrl`). `POST /api/uploads/video` requires sign-in, checks MP4/MOV/WebM by magic bytes, caps at 30 MB and rate-limits; it uses the same storage as photos (local disk or UploadThing). Local `/api/uploads/*` now answers byte-range requests so Safari can play video. Shown as a player on the item page. Limitation: Vercel serverless request bodies are about 4.5 MB, so longer clips fail on the deployed site (they work locally); direct-to-UploadThing upload is not built. Video is not AI-analysed. Unit tests pass (152); not tried with a real clip.
- 2026-11-15: Removed the RideBoard/pickup feature at the owner's request: the page, `/api/pickups` and `/api/drivers` routes, the `components/rideboard` UI, the Rides tab, the "Request pickup help" panel on item pages and the seeded pickups/drivers. Dormant backend pieces remain (`lib/pickups`, pickup/driver queries and types, `tests/unit/pickups.test.ts`, the `pickups`/`drivers` collections); old rows in the database are not deleted. Restore from git history if needed. This drops the pickup step from the AGENTS.md demo-critical path.
- 2026-11-15: Reverted the WillItFit rebrand at the owner's request; the product is ShareFly again. The "Giving something away should take seconds" line is removed from the landing hero and README; the hero now leads with "Finding something you need should feel effortless."
- 2026-11-15: The demo is in Los Angeles, so seed data and the demo script now use LA neighborhoods (Priya: USC / Exposition Park; Hardika and Tarbi: Downtown Los Angeles; the bed: Koreatown) and LA neighborhoods are listed first in suggestions. Houston stays available because the Matterport dataset covers it. Requires `npm run db:seed -- --reset` to take effect in an existing database. Unit tests pass; e2e not re-run.
- 2026-11-15: Rebranded the visible product name from ShareFly to WillItFit (header, page titles, sign-in, landing copy, README, error text). Internal names stay `sharefly` on purpose so nothing breaks: the MongoDB database name, `ATLAS_DB` default, `package.json` name, Mongo `appName`, log prefix and the repo folder. The helping-hands logo is unchanged. Old docs (AUDIT, IMPLEMENTATION_PLAN, earlier decisions) keep the old name as history.
- 2026-11-15: Added a saved cart (MongoDB `cart` collection, unique per person and listing). Items are added from the item page; `/cart` lists them with size and price, and "Ask for all" (`POST /api/cart/request`) records interest and notifies each owner, then clears those items. There is no checkout or payment, and combined fit/pickup for the whole cart is not built. Unit test covers the input schema only; the routes and page are untested and not tried in the browser.
- 2026-11-15: A new or edited wishlist no longer matches items that were already listed. `runMatchingForWishlist` only considers listings published after the wishlist was created; the match appears when someone uploads a fitting item (`runMatchingForListing`, unchanged). This narrows the two-way matching described in the product brief at the owner's request. Not covered by a unit test (the function reads the database); existing matches in the database are untouched.
- 2026-11-15: At the owner's request, the Matterport stage no longer shows its hint, status and attribution/stand-in footnote, and the room page no longer shows the visible "Based on ... Data: CoStar" note. The room-source note stays in the page as screen-reader-only text (e2e tests assert it); status text still shows on errors. Visible CoStar/Matterport attribution may still be required by the sponsors' terms; confirm before publishing.
- 2026-11-15: Furniture in the room planner, the Matterport stage and AR uses the listing's own 3D scan when it has one (`lib/room/scan-model.ts`), stretched to the confirmed width/depth/height so it matches the fit checks, and falls back to the procedural measurement-based model while loading, on any load error, or when there is no scan. A scan is only ever used for the listing it was uploaded to; scans of other items are not substituted for lookalikes. Unit tests and `next build` pass; not tried with a real scan.
- 2026-11-15: A fresh 3D scan auto-fills and saves width/depth/height from its bounding box when the listing has no size (values outside 2 cm to 10 m are ignored); the size form stays editable afterwards. "View in 3D" opens the owner's scan (USDZ re-exported to GLB in the browser with three.js GLTFExporter) instead of the stand-in shape. A browser cannot drive the iPhone LiDAR scanner, so scanning itself stays in Reality Composer. Unit tests and `next build` pass; not tried with a real scan.
- 2026-11-15: Owners can attach their own 3D scan (`.usdz` from Reality Composer / Object Capture, or `.glb`) to a listing via `POST/DELETE /api/listings/[id]/model`. Validated by magic bytes (GLB header; USDZ is a ZIP whose first entry is a USD file), 30 MB cap, owner only. Shown with three.js (USDZLoader/GLTFLoader) and an AR Quick Look link on iPhone. "Use the scan's size" pre-fills width/depth/height from the model bounding box for the owner to confirm. Limitation: Vercel serverless request bodies are about 4.5 MB, so larger scans need local storage or a direct-to-UploadThing upload (not built). Unit tests and `next build` pass; not tried with a real iPhone scan.
- 2026-11-15: Owners can add up to 8 self-named measurements per listing (`extraMeasurements`, meters, Zod-validated, shown as "from the giver"). They are informational and never used for fit checks, which still need width, depth and height. The screenshot reader also returns other printed, labelled sizes. "Learning" is not model training: `popularMeasurementLabels()` aggregates names people already used and offers them as suggestions and as prompt hints. Unit tests pass (145); not tried with a live key or in the browser.
- 2026-11-15: Owners can pre-fill a listing size from a screenshot (iPhone Measure or Reality Composer) via `POST /api/ai/read-measurements`. The model may only transcribe numbers printed in the image, never estimate from the object; values outside 2 cm to 10 m are dropped; the mock and none providers return nothing. Results only fill the form and the owner must press Save size. Not yet verified on a real screenshot with a live key; `.usdz` bounding-box import is not built.

- 2026-11-14: CoStar supplied Matterport connection guidance. Tours use a lazy `my.matterport.com/show/?m=` iframe, choosing unit, floor-plan, then community ids. The Model API is server-only, timeout-bounded, Zod-validated, and falls back to the square-footage estimate when unavailable. - 2026-11-14: "View in 3D" (AR) uses Google `<model-viewer>`: WebXR on Android Chrome, AR Quick Look on iOS (USDZ converted on device). Loaded as the prebuilt CDN bundle because the npm package's three peer range (^0.183) conflicts with ours (0.187); the bundle carries its own three, so the console shows a harmless "multiple instances of three.js" warning.
- The AR model is the same procedural shape the planner draws (`lib/room/model.ts`), exported to GLB in the browser. It is a to-scale stand-in, not a scan, and the UI says so. AR scale is locked (`ar-scale="fixed"`) and the button only appears when the giver has entered measurements; otherwise it explains why it is unavailable.
- Scene Viewer (Android's non-WebXR fallback) is not enabled: it needs a public URL to the model and our model is a client-side blob.
- 2026-11-14: Laptop alternative to AR: "In a photo of my room". The person marks a line of known length (e.g. a door) to set pixels-per-meter, then the same procedural model is drawn over the photo with an orthographic camera, plus turn and camera-angle sliders. It is labeled approximate (a flat photo has no depth; accurate near the measured line). The photo is never uploaded; it stays as a local object URL. "Door height (often 6'8\")" is only a fill-in suggestion the person confirms.
- 2026-11-14: HEIC support via `heic-to` (LGPL-3.0, maintained, current libheif) rather than `heic2any` (MIT wrapper, but unmaintained and ships a 2020 libheif that fails on newer iPhone photos; libheif is LGPL either way). Format is detected by magic bytes (`lib/image-decode.ts`) because browsers often report HEIC with an empty MIME type. Native decode is tried first (Safari), the converter is lazy-loaded otherwise. The server still only accepts JPEG/PNG/WebP; listing photos are re-encoded to JPEG on the device before upload.
- 2026-11-14: Room photo now places the item automatically instead of asking for a measurement first. A single photo has no depth, so we estimate the camera (about 1.4 m high, tilted 8 degrees down, lens from EXIF FocalLengthIn35mmFilm when present, else 26 mm) and render with a matching perspective camera; taps map to floor positions. Labeled as an estimate. Marking a door (floor to top) is optional and solves the camera height exactly (`cameraHeightFromVertical`). Considered but not done: AI vision or monocular depth models (large downloads, still approximate, and the AI provider is off by default). Calibration supersedes the orthographic pixels-per-meter approach recorded above.
- 2026-11-14: Preview polish stays procedural instead of shipping a downloaded sofa mesh: a fixed mesh would have to be stretched to the giver's measurements (distorting cushions and legs) and adds an asset and licence to track. Rounded parts are laid out from the measurements so the outer box is exact. Cloth is a tiny canvas-generated normal map with texture coordinates in meters; it is skipped where there is no canvas (server, unit tests). Lighting, shadow, zoom and reset use `<model-viewer>` features rather than a second React Three Fiber scene, so what people inspect is the same GLB that AR places. Panning is disabled so "Reset view" always returns to the same framing. The viewer text now says colour and styling are illustrative.
- 2026-11-14: Listing detail now keeps the uploaded photo visible as the visual source of truth beside the dimension-locked generated GLB. A single photo is not treated as a reliable 3D scan; the viewer uses the photo as visual reference and confirmed giver measurements for scale, while the photo remains authoritative for shape, finish, and condition.
- 2026-11-14: Replaced all checked-in seed illustrations with locally stored Unsplash photographs. Sources and the Unsplash License are recorded in `public/seed/PHOTO_SOURCES.md`; reused photos are explicitly treated as generic demo imagery, not product identity claims.
- 2026-11-14: CoStar reference spaces. One compact record per apartment floor plan, written by `scripts/import-costar.ts` to `data/reference-spaces.json` (gitignored). Rent 0 becomes null ("not provided"). Matterport ids are kept at community, floor-plan and unit level (types 36/234, `videoKey`); no media is downloaded.
- Room size from a floor plan is an ESTIMATE: main room = floor-plan sq ft x share (studio 80%, 1 bed 40%, 2 bed 30%, 3+ bed 25%), 1.25:1 shape, 8 ft ceiling (the kit has none). Editable, always labelled. Smaller end of the sq ft range is used.
- Rooms store a JSON `source` snapshot (server-built from the space id; clients never supply it) so the source label survives dataset changes.
- Max-rent filter hides floor plans with unknown rent rather than assuming they are cheap.
- E2E uses a synthetic fixture (`tests/fixtures/reference-spaces.sample.json`), not CoStar data, so tests never need the kit.

- 2026-11-14: Map-picked rooms now ARE the Matterport tour. `BundleRoomStage` self-hosts the Bundle SDK player (`npm run matterport:bundle`, git-ignored per Matterport's SDK license), exports each listing piece with confirmed measurements to a to-scale GLB (`lib/room/glb.ts`) and adds it via `mp.gltfLoader`. Placement is a runtime overlay at the viewer's sweep (not saved, not calibrated). Rooms with a source no longer show the R3F planner; dimension-only rooms still do. Room creation is either "pick a 3D room on the map" (size from the scan, only spaces with a tour are listed, no manual numbers) or "enter dimensions", never both. Without `NEXT_PUBLIC_MATTERPORT_SDK_KEY` the room falls back to the view-only tour with a notice.
- 2026-11-14: "View in your room" renamed "View in 3D" (it is a to-scale model viewer + phone AR, not the user's room). The "In a photo of my room" tab was removed from the viewer; `PhotoPlacer` is now unused.
- 2026-11-14: UploadThing is an optional photo store (`STORAGE_PROVIDER=uploadthing` plus `UPLOADTHING_TOKEN`), chosen because Vercel's disk is read-only. Uploads keep going through `/api/uploads` so magic-byte sniffing and the size cap run before anything leaves the server; the token never reaches the browser. Stored photo URLs may now be `https://<id>.ufs.sh/f/...` in addition to local `/api/uploads/...` and `/seed/...`; no other host is accepted. It falls back to local disk without a token. SQLite remains local, so UploadThing alone does not make a Vercel deploy persistent.
- 2026-11-14: Added `.github/workflows/ci.yml` (typecheck, unit tests, build on push to main and on PRs). It uses no secrets and the local fallbacks, so Atlas and UploadThing are never called from CI. Lint is left out until the ESLint `react-hooks` plugin config error is fixed. Deployment to Vercel is expected to use Vercel's Git integration with env vars set in the Vercel dashboard, not a workflow.

- 2026-11-14: Replaced SQLite (better-sqlite3) with MongoDB as the primary store, because SQLite cannot persist on Vercel's read-only disk and the team already has an Atlas cluster. Same function names in `lib/db/queries.ts`, now async. Docs use the string id as `_id` and camelCase fields. Listing photo is denormalized onto the listing, room placements are embedded in the room, and unique indexes replace `INSERT OR IGNORE`. Trade-off: no cross-collection transactions, so cascades (deleting a wishlist removes its matches) are done in code. Existing SQLite data is not migrated; run `npm run db:seed`. E2E uses its own database (`ATLAS_DB=sharefly_e2e`) so `db:seed --reset` never touches real data.

- 2026-11-15: Matterport overlay furniture is placed at the sweep's `puckPosition` (floor), not `position` (camera height), in front of the viewer along the camera yaw, and re-placed on every sweep change unless the user has moved or removed that piece. "Moved" is inferred by comparing the node position to the last position we set, so no extra state is kept in the scene. Trade-off: if the player will not return node positions, all pieces follow the viewer.
- 2026-11-15: The Bundle `mp.transformControls` component is driven only through `selection`, `mode`, `showX/Y/Z` and `size`. It has no `visible` input (sealed inputs throw), and only HOVER and DRAG events, so drag end is inferred from a 300 ms gap in DRAG events. Tour navigation (`mp.input.userNavigationEnabled`) is disabled while hovering or dragging the gizmo so gizmo use does not also walk, look or reselect. Rotate exposes only the vertical axis so furniture stays on the floor.
